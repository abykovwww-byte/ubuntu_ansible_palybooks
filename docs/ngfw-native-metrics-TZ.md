# ТЗ: Штатные метрики PT NGFW и экстремальное сравнение с EDR и без EDR

Источник: согласованное поручение пользователя, переданное куратором из чата
01a12f41-061b-7221-80d4-50f46ad55718. Принято 2026-10-12. Этот файл —
самостоятельная проверяемая фиксация требований; факты выполнения находятся в
RUN-STATE и evidence. Исторические снимки не являются текущим состоянием.

## 1. Цель и границы

Поднять штатный сбор, локальное хранение и отправку на внешний сервер;
выполнить реальные экстремальные сравнительные A/B испытания и воспроизводимый
отчёт. Главный результат — фактическая нагрузка, сопоставимые метрики, влияние
EDR и установленный либо явно не достигнутый предел. Git/CI/Ansible/панель —
средства. Только существующий изолированный лабораторный стенд, не продуктивный
корпоративный NGFW. Изменения доставлять Git → PR → CI → merge → Ansible.
Не заменять доставку hot edits/SCP, не публиковать секреты и не придумывать
адрес внешнего сервера. Точные недостающие доступы/реквизиты фиксировать;
независимую работу завершать. Живым стендом и переключением EDR управляет
один ведущий исполнитель; агенты работают в непересекающихся файлах.

  испытания 22–25.09.2026, не заключение производителя.

Штатный Telegraf NGFW → совместимая InfluxDB на локальном сервере стенда вне
тестируемой VM. Версии/input plugins/источники — из фактической поставки PT,
без автоматического обновления до latest. Grafana базово не нужна: API БД и
извлечение определений/запросов Linux.json, PT NGFW.json, pt-ngfw-lite.json,
cluster/hardware. Если расчёт не воспроизводится — исследовать Grafana.
Совместное физическое размещение требует выделения ресурсов и измерения
конкуренции, исхода HOST_LIMITED. CPU ОС не равен полезной загрузке DPDK.
Нет подтверждения PT, что только Telegraf точен или все прежние замеры неверны.

Исторически: NGFW 1.11.1 build 1750 Debian 12, KVM 4 vCPU/16 GiB,
vxagent 5.0.0.0, AuditD 116 правил, guest 10.77.0.20,
клиент 10.77.10.10 → NGFW → приёмник 10.77.20.10. Проверить всё заново.
15 300 соединений 25.09 — не предел: VM не упала, контроллер остановился по
18.9585/s < 19/s, хотя +100/мин выполнено. /proc/stat в measure_probe.py
измеряет ОС, не штатный dataplane.

## 3. Каталог и наблюдение

Фактически доступные штатные загрузка обработки, интерфейсы/байты/пакеты,
drops/сессии/ошибки/очереди; ОС CPU по ядрам user/system/idle/iowait/steal,
RAM/HugePages/I/O/диск; процессы pt-ngfw/Telegraf/vxagent/auditd;
AuditD lost/backlog/backlog_limit/EPS/рост журнала; offered/achieved load,
errors/loss/latency/retransmits/resources генератора и приёмника; ошибки,
задержка, очередь сбора/записи/экспорта. Недоступные показатели не выдумывать.
Для каждого: имя, источник, единица, counter/gauge, интервал, формула,
ограничение. Начать со штатного интервала; повышать частоту только после
проверки observer impact, одинаково A/B. Пропуск не ноль, неизвестное явно
неизвестно. CPU ОС и NGFW раздельно.

## 4. Хранение и экспорт

Локальное — внутри стенда без внешней зависимости. InfluxDB и основной архив
вне NGFW VM. Raw ≥30 суток, архив испытаний ≥90 суток; дисковая очередь ≥24 ч
при реальном пиковом потоке +30% запаса; расчёт по реальному расходу.
Endpoint/тип/API/учётные данные/retention внешней стороны — параметры,
существующий сервер только по подтверждённым реквизитам. Проверяемое временное
назначение допустимо, но не равно приёмке внешней доставки.
Экспорт не блокирует локальную запись; timestamps/поля/теги/точность сохранены;
очередь/checkpoint переживают restart, drain ограничен. Повторы без двойного
учёта, read-back внешней стороны. Проверить offline, накопление, restart,
reconnect/replay и совпадение данных. Отдельно отказ локальной БД,
гарантированная длительность source buffering и обнаружение потерь.
Память Telegraf не crash-safe; disk buffering проверить для установленного
бинарника. Backup/restore и повторный отчёт. Очередь не гарантирует отсутствие
потерь при любом отказе.

## 5. Профили

A: EDR не установлен, штатный административный аудит.
B: EDR установлен + полный исследуемый AuditD (воспроизвести 116 правил).
Остановка службы с прежним EDR AuditD не равна A. Разница агента и AuditD
означает измерение полного профиля. Build, full policy/config hashes,
security features, VM resources, topology, generator/receiver config,
наблюдение/log forwarding одинаковы. Никаких скрытых изменений.

## 6. Экстремальная нагрузка

Короткий допуск и быстрый разгон сразу к верхней нагрузке. Проектные начальные
цели, не паспорт PT:

| Сценарий | Начальная цель/эскалация |
| --- | --- |
| TCP throughput | ≥900 Mbps; выше при подтверждённой ёмкости пути |
| UDP | малые пакеты — максимальный подтверждённый PPS; крупные — полоса; различать payload/frame |
| Short TCP | ≥5000 CPS при подготовленном генераторе |
| Held sessions | 20000, затем 60000 при достаточных FD/портах/ресурсах; подтверждённые обмены |
| HTTP | максимальная воспроизводимая интенсивность |
| DNS | ≥5000 qps, затем максимум генератора |
| Mixed | высокий bandwidth + PPS + connections, фиксированные доли |

До NGFW-пути подтвердить capacity контрольным путём, проверить порты/FD/cgroup/
memory. Недостижимая цель — generator/host limited, не предел NGFW.
При деградации сохранить окно и уточнить границу крупными шагами/делением
диапазона; при отсутствии лимита повышать в подготовленных пределах.
1000 ACL/200 NAT не доказывают покрытие: фиксировать matched rules/путь.

## 7. Протокол и безопасность

Каждый сценарий A→B→возвратный A, минимум 3 валидных парных сравнения;
чередовать порядок последующих блоков. Offered load пары одинаковая;
устойчивый предел каждого профиля отдельно. Разгон/стабилизация ≤60 s,
measure 5 min, recovery ≥2 min и до нормализации; набор held отдельно.
Endurance 60 min каждого профиля на максимальной устойчивой нагрузке.
Опасный отказ ради количества не повторять. CPU100% не автоматическая
остановка. Исходы NGFW_LIMIT, GENERATOR_LIMITED, HOST_LIMITED,
INVALID_MEASUREMENT, SAFETY_STOP. Snapshots/rollback обоих профилей и проверка
изоляции до испытаний. При отказе управления/restart/OOM/критическом диске/
потере обязательного аудита остановить нагрузку, восстановить. Не терять
failed windows/генераторские данные.

## 8. Анализ и приёмка

Manifest: run_id/profile/workload/repeat/time windows/offered load/versions/
config hashes. Не менять смысл native metrics ради тегов. Прямые API запросы
выбранной InfluxDB, raw export, воспроизводимый анализ. Achieved throughput/
PPS/CPS/RPS, loss/errors, p50/p95/p99 из raw или корректных гистограмм,
не среднее готовых quantiles; native NGFW + ОС отдельно, EDR/AuditD,
completeness/observer impact, delta A/B, разброс, stop reason.
Исследовательский критерий: успешная производительность падает >5%,
воспроизводимо и больше control scatter; не норматив PT. Latency/errors/
capacity отдельно. Stable/overload не усреднять. Локальный AuditD,
центральная регистрация и фактический приём EDR events — отдельные факты;
недоступная консоль — пробел.

Приёмка: живой local DB сбор/каталог; анализ без Grafana; durable external
replay/readback либо конкретный внешний блокер; настоящие экстремальные A/B
и 60 min endurance; все окна сохранены; предел/причина установлены либо
явно не установлены; воспроизводимые выводы; стенд восстановлен.
При лимите генератора: «EDR проверен до достигнутой нагрузки; предел NGFW
не установлен». Поставка: это ТЗ, configs, catalog, exporter/restore,
workload plans, analyzer, raw evidence, report, короткий RUN-STATE.
Отдельно сообщать local validation, CI, commit/push, deploy, live и пробелы.
