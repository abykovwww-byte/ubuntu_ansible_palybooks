# Server-side Telegram archive collection

The opt-in `telegram_collector` role moves the existing read-only collector
to abykovserv. Windows remains an MCP reader. Existing PostgreSQL rows, cursors,
owner-approved chat scope, media files and relative media paths are reused.
No Telegram messages are sent, edited or deleted by collection or acceptance.

The source under `roles/telegram_collector/files` becomes the collector's
deployment authority. The original Windows collector is a rollback copy until
the first verified server `ok` run; its two scheduled tasks must be disabled
before the migrated session starts on the server. They may be removed after
acceptance. Do not run the same Telegram authorization concurrently on two hosts.

## Execution and network boundary

The oneshot Compose service runs as the existing media owner's numeric UID/GID,
with a read-only root filesystem, no capabilities, no published ports and only
the external `vpn_clients` Docker network. Ansible refuses deployment unless
that existing network is `Internal=true`. The Linux Telegram client always
selects `socks5://vpn-egress:1080`; missing/unavailable VPN never selects direct
egress. The gateway's transport network is not attached to the collector.

The database uses a bind-mounted Unix socket at `/run/postgresql`, not TCP,
Tailscale or the VPN. Its only new HBA rule is `local tgarchive tg_writer
scram-sha-256`, before the existing local reject rule. Owner/reader access and
all existing exact TCP and SFTP source restrictions remain as before. PostgreSQL
keeps its existing internal administration socket and adds `/archive-socket`.
When the collector is enabled, a loopback listener is also added so PostgreSQL
can start its local sockets even if its Tailscale address is not yet present.
No loopback TCP HBA allow rule is added; collection still uses the Unix socket.

The existing `/srv/data/tg-archive/media` is mounted at `/media`. The local
adapter preserves complete-listing fsck, symlink rejection, `.part` writes,
size/SHA verification and atomic rename before DB `done`. The media route check
does not invoke Tailscale for local storage. VPN enforcement belongs to the
Telegram connection and the isolated container network.

One `telegram-collector.timer` invokes one oneshot service every 30 minutes,
24 hours a day. `Persistent=true` catches a missed calendar activation after
boot. systemd does not overlap an already active oneshot; the shared data
directory also has the OS lock, and PostgreSQL has a session advisory lock.
There is no competing daily/one-chat schedule. A failure retries at the next
timer activation. An overlong run is bounded to four hours and container cleanup
runs when the service stops. Only filtered JSON counters/statuses persist in
the private reports directory; container output is not retained.

## Private preparation and cutover

1. Review, test and merge the IaC change. No session, API credential, chat list,
   owner approval receipt or real run report belongs in the public repository.
2. On Windows run `scripts/pause-windows-telegram-collector.ps1`. It disables
   `Telegram Archive daily` and `Telegram Archive work hours` and refuses cutover
   while an existing scheduled collection is still running. Let any manual
   collector finish too. The preparation command obtains the existing OS lock.
3. Use the original Windows project's interpreter to run the IaC helper:

   ```powershell
   & 'C:\Users\albykov\Documents\Jira\telegram-archive\.venv\Scripts\python.exe' `
     scripts\prepare-telegram-collector.py `
     --source 'C:\Users\albykov\Documents\Jira\telegram-archive'
   ```

   It validates the current allowlist and transfers the existing Windows Vault
   session, API id/hash, selected chats, approval receipt and quota settings over
   authenticated SSH stdin into a random private server staging directory.
   It never transfers the local DB owner/reader password or SFTP private keys,
   prints only the staging receipt, and never stores the session in a local file.
4. After merge, on the server run interactively, using the exact returned path:

   ```sh
   cd /opt/ubuntu_ansible_palybooks
   git pull --ff-only
   sudo .venv/bin/python scripts/activate-telegram-collector.py /home/abykov/.tg-collector-migration-RECEIPT
   ```

   The helper validates the staging location/permissions, installs private input
   files under `/etc/ansible/telegram-collector-private` and enables only
   `telegram_collector_enabled` in server-local overrides. It preserves other
   override text, removes the verified staging directory, then runs the focused
   `playbooks/telegram-collector.yml` through the existing local apply script.
   The existing `telegram_archive_enabled` and `vpn_egress_enabled` settings must
   already be true. The collector receives only writer credentials generated by
   Ansible, a private session mount, and API credentials; it gets no owner/reader
   password or general admin SSH key.
5. If the apply fails after private installation, fix the IaC cause and retry
   `sudo ./scripts/apply-local.sh playbooks/telegram-collector.yml`. Staging was
   consumed, but the root-private inputs remain. Do not export/regenerate an
   authorization to fix a deployment error.

## Live acceptance

Run `sudo systemctl start telegram-collector.service` once after apply, then
inspect its result and the newest private JSON report. Require a completed
`status=ok`, `exit_code=0`, all configured chats, `fsck_status=ok`, and independent
DB read-back of `sync_run`, chat `last_ok_at`, cursor progression and media queue.
Do not copy message bodies, filenames or private chat identifiers into reports.
Inspect `vpn_clients` membership and confirm the collector lacks the gateway's
transport network. Exercise a bounded synthetic connection from the actual
collector network with the proxy absent and require refusal; restore the
normal configuration afterwards without changing other gateway consumers.

Observe the next timer-triggered run without Windows collection running and,
for independence acceptance, with Windows powered off. An active timer, image
build, reachable Bot API or merged PR alone does not prove MTProto collection.
Do not create test messages in work chats. Natural cursor/media changes or
synthetic isolated fixtures supply the data-path evidence.

Windows MCP still needs connectivity to the archive when a user queries it.
Windows uptime or its VPN state no longer controls server-side collection.

## Rollback

Stop/disable `telegram-collector.timer`, stop its service and verify its
container has exited **before** re-enabling Windows collection with the same
authorization. Keep the database and media. Set the collector flag false through
local overrides and reapply the focused archive playbook if retiring the server
collector. Removing the local writer socket/HBA rule does not remove data.
Never restart both collectors as a rollback test.

## Validation boundary

Local Windows checks cover collector logic and rendered IaC. Linux CI builds the
locked image and exercises POSIX session/media boundaries. Production acceptance
additionally requires server access, private staging, interactive sudo apply,
a completed collection and a later timer run. Report each layer separately.
