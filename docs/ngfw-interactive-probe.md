# Одноразовый интерактивный канал измерителя NGFW

`interactive_probe.py` соединяет существующий runner с read-only пробником, когда
гостевой вход и sudo требуют интерактивной аутентификации. Он не настраивает SSH,
не устанавливает ключи, не меняет sudoers и не сохраняет пароль. На гипервизоре
запускается только от обычного оператора; запуск брокера через host sudo запрещён
самим кодом. Единственная команда sudo выполняется внутри `ngfw@10.77.0.20`.

Это временный измерительный канал, **не допуск к нагрузке**. Температурные пороги,
отрицательная проверка изоляции, snapshot/rollback, фактические правила AuditD и
остальные проверки T00 остаются обязательными. Изменять правила аудита, чтобы
обойти блокировку измерителя, нельзя.

## Запуск

Доставить через согласованный Git/IaC workflow рядом с существующим
`/srv/apps/ngfw-lab/measure_probe.py`. Штатный apply не запускает брокер.
Сначала открыть интерактивную SSH-сессию **на abykovserv**; нужен TTY. Из неё:

```bash
cd /srv/apps/ngfw-lab
python3 interactive_probe.py broker --lifetime 1800 \
  --process-name auditd --process-name rsyslogd --process-name vxagent
```

Один раз интерактивно вводятся гостевые пароль входа и пароль sudo. Не передавать
их аргументами, в файлах, environment, Git, shell history или через запись
терминала. Это не пароль хоста `abykovserv` и не пароль MNGT admin. SSH проверяет
уже доверенный host key; неизвестный/изменившийся ключ не принимается автоматически.
Авторизация ограничена 120 секундами, повторный ключевой перебор не производится.

После успешного гостевого root-допуска брокер печатает путь наподобие
`/tmp/ngfw-probe-XXXXXXXX/argv.json`. Это приватный несекретный список аргументов,
не пароль. **Сохранить этот терминал открытым.** Второй SSH-терминал на том же
хосте от того же оператора использует фактически напечатанный путь:

```bash
cd /srv/apps/ngfw-lab
python3 runner.py measure-check \
  --measurement-argv-file /tmp/ngfw-probe-XXXXXXXX/argv.json
```

Здесь `XXXXXXXX` — placeholder, не буквальный путь. Только после приёмки T00
этот же argv-файл подключается к согласованному короткому прогону через
`--measurement-argv-file`; `--measurement-config` и `--run-context` остаются
обязательными для расширенного формального прогона.

`--process-name` фиксирует выбранные Linux comm имена на всю сессию; они должны
совпадать с измерительной конфигурацией. Дополнительно разрешены стандартные
`auditd`, `rsyslogd` для discovery. Если код пробника или выбранные имена изменены,
брокер завершается и открывается заново; он не принимает новое исполнение от клиента.

Если используется проверенный baseline выделенных busy-poll потоков, вместо
`--process-name` передать тот же приватный файл, который будет использовать runner:

```bash
python3 interactive_probe.py broker --lifetime 1800 \
  --measurement-config /private/measurement.json
```

Файл целиком проходит `measurement.validate` **до SSH-аутентификации**. Значения
`process_names` и разрешённого `guest_busy_poll_baseline` фиксируются на весь сеанс.
Гостю передаются только заранее выбранные числовые PID/TID для read-only снимков;
ни callback, ни исполняемого выражения из конфигурации нет. В этом режиме и
`measure-check`, и сам прогон должны получать тот же `--measurement-config`:
исходник без зафиксированных thread targets или с другими PID/TID отвергается.
Изменение baseline требует закрытия и повторного запуска брокера, а сам baseline
не является доказательством допустимости исключения нагрузки без исходного T00.

## Ограничения канала и STOP

- Брокер держит один SSH/PTTY-сеанс. Пароли передаются напрямую между терминалом,
  SSH и гостевым sudo, не распознаются и не сохраняются брокером.
- В госте исполняется только проверенный исходник существующего пробника в памяти.
  Файлы, ключи, службы, слушающие порты и настройки в госте не создаются.
- Каталог брокера имеет `0700`, Unix-сокет и argv-файл `0600`. TCP/HTTP listener
  отсутствует. Проверяется Linux peer UID. Клиент передаёт только SHA256 исходника
  и свежий nonce; произвольные присланные программы никогда не исполняются.
- Разрешены строго определённые варианты исходника: выбранные имена процессов и
  `inventory=false/true`. Запросы сериализуются, каждый вызывает новый snapshot.
  Сохранённых снимков, подставляемых при ошибке, нет.
- Каждый снимок ограничен 9 секундами; несовпадение nonce, повторный guest monotonic,
  EOF, неправильный JSON или таймаут завершают канал. Runner получает ошибку,
  а не старые данные. Общий лимит сессии — максимум 30 минут, максимум 2000 запросов.
- В простое отслеживается и гостевой PTY: EOF или неожиданный вывод закрывают
  брокер немедленно, без ожидания следующего runner-запроса или 30-минутного лимита.
- Гостевой процесс имеет собственный таймер завершения. Ctrl+C, закрытие SSH,
  SIGHUP/SIGTERM, потеря гостя и истечение срока завершают сессию. Брокер закрывает
  только свой дочерний SSH-процесс, без `pkill`/сигналов чужим службам.
- При нормальном завершении удаляются только созданные этим запуском socket и
  argv-файл с совпадающими filesystem identities; незнакомые/заменённые файлы не
  удаляются рекурсивно. После SIGKILL могут остаться приватные временные файлы;
  они не содержат пароли и не означают живой канал.

PTY и отдельный Python-процесс являются частью наблюдателя. Их накладные расходы
надо учитывать в T20 и сохранять одинаковыми между A/B/C. Ограничение 30 минут
предназначено для короткого пилота, не для полной многочасовой матрицы.

## Приёмка перед трафиком

1. Получить два свежих `measure-check`/снимка, проверить разные monotonic и актуальные
   AuditD inventory hashes; успешный вход сам по себе ничего этого не доказывает.
2. Проверить, что модифицированный исходник отвергается без исполнения.
3. Проверить прекращение канала по Ctrl+C и ошибку следующего клиента; тестовый
   runner не должен продолжать нагрузку с устаревшим снимком.
4. Повторно авторизовать канал для самого согласованного прогона. Пароли не
   включать ни в артефакты T00, ни в журнал оператора.

Локальные unit tests проверяют source allowlist, протокол и freshness; Linux-only
проверки дополнительно проверяют private Unix socket и точечную очистку. Они не
заменяют интерактивную SSH/sudo приёмку на реальном госте.
